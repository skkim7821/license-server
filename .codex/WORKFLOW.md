# AI Development Workflow

이 문서는 AI 코드 에이전트(Codex 등)가 이 저장소에서 작업할 때 따라야 하는 개발 절차를 정의한다.  
모든 구현 작업은 아래의 단계적 프로세스를 반드시 따른다.

목표는 다음과 같다.

- 과도한 설계 방지
- 안정적인 코드 품질 유지
- 사이드 이펙트 최소화
- 보안 문제 예방
- 사용자 흐름 보호
- 배포 가능한 수준의 코드 생성

---

# 1. 계획 수립 (Planning)

작업을 시작하기 전에 반드시 다음을 수행한다.

- 문제를 명확하게 정의한다
- 구현 목표를 정리한다
- 필요한 변경 범위를 파악한다
- 기존 코드 구조를 이해한다
- 영향을 받을 수 있는 영역을 식별한다

가능하면 **구현 계획을 먼저 작성한다.**

---

# 2. 계획 검토 (Plan Review)

작성된 계획이 적절한지 검토한다.

검토 항목

- 요구사항을 정확히 충족하는가
- 문제 해결에 적절한 접근 방식인가
- 기존 아키텍처와 충돌하지 않는가
- 불필요하게 복잡한 구조는 아닌가

---

# 3. 계획 검증 (Plan Validation)

계획 검토가 올바르게 이루어졌는지 다시 검증한다.

확인 사항

- 빠진 요구사항은 없는가
- 논리적인 오류는 없는가
- 다른 더 단순한 해결 방법은 없는가

---

# 4. 과도한 설계 방지 (Scope Control)

다음 사항을 확인한다.

- 현재 문제 해결에 필요한 최소한의 구현인가
- 미래 확장을 과도하게 고려하지 않았는가
- 불필요한 추상화가 포함되어 있지 않은가

---

# 5. 구현 (Implementation)

계획이 충분히 검토되었다면 구현을 진행한다.

구현 원칙

- 기존 코드 스타일을 유지한다
- 명확하고 읽기 쉬운 코드를 작성한다
- 불필요한 복잡성을 피한다

---

# 6. 구현 검토 (Implementation Review)

구현이 다음 기준을 충족하는지 확인한다.

- 목표한 기능이 정확히 동작하는가
- 요구사항이 모두 반영되었는가
- 코드 가독성이 충분한가

---

# 7. 버그 및 보안 검토 (Bug & Security Review)

다음 사항을 점검한다.

- 잠재적인 버그
- 예외 처리 누락
- 보안 취약점
- 입력 검증 부족
- 데이터 처리 오류

---

# 8. 개선 사항 검토 (Improvement Review)

개선 과정에서 새로운 문제가 생기지 않았는지 확인한다.

- 기존 기능이 깨지지 않았는가
- 회귀(regression)가 발생하지 않았는가

---

# 9. 코드 구조 점검 (Code Structure Review)

다음 기준을 확인한다.

- 지나치게 큰 함수가 있는가
- 지나치게 큰 파일이 있는가
- 책임이 명확하게 분리되어 있는가

필요하다면

- 함수 분리
- 모듈 분리
- 구조 정리

를 수행한다.

---

# 10. 코드 재사용 검토 (Reuse Check)

다음 사항을 확인한다.

- 이미 존재하는 유틸리티를 활용할 수 있는가
- 기존 컴포넌트를 재사용할 수 있는가
- 중복 코드가 생기지 않았는가

---

# 11. 사이드 이펙트 검토 (Side Effect Check)

다음 사항을 확인한다.

- 다른 모듈에 영향을 주지 않는가
- 전역 상태를 변경하지 않는가
- 예상치 못한 동작이 발생하지 않는가

---

# 12. 전체 변경 사항 재검토 (Full Change Review)

전체 변경 사항을 다시 검토한다.

- 변경 범위가 적절한가
- 코드 흐름이 자연스러운가
- 논리적 오류가 없는가

---

# 13. 불필요한 코드 정리 (Dead Code Cleanup)

구현 과정에서 불필요해진 코드가 있다면 제거한다.

- 사용되지 않는 함수
- 사용되지 않는 변수
- obsolete 로직

---

# 14. 코드 품질 검토 (Code Quality Check)

다음 기준을 확인한다.

- 코드 가독성
- 유지보수성
- 일관된 스타일
- 명확한 변수명

---

# 15. 사용자 흐름 검증 (User Flow Validation)

사용자 입장에서 다음을 확인한다.

- 기능 사용 흐름이 자연스러운가
- UX에 문제가 없는가
- 예상치 못한 동작이 없는가

---

# 16. 관련 영역 반복 검토 (Related Area Review)

검토 중 발견된 문제와 관련된 영역을 반복적으로 점검한다.

- 의존 모듈
- 관련 기능
- 데이터 흐름

필요하다면 여러 차례 재검토한다.

---

# 17. 배포 가능성 검증 (Production Readiness)

다음 질문에 답할 수 있어야 한다.

이 코드는 **바로 배포해도 될 수준인가?**

확인 항목

- 안정성
- 보안
- 코드 품질
- 유지보수성

---

# 18. 커밋 및 PR 생성 (Commit & Pull Request)

모든 검토가 완료되었다면 다음을 수행한다.

- 의미 있는 커밋 메시지 작성
- 변경 내용 요약
- Pull Request 생성

PR에는 다음을 포함한다.

- 변경 목적
- 주요 변경 사항
- 영향 범위
